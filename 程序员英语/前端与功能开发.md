# 前端与功能开发

返回 [[程序员英语/README|程序员英语]]

### 组件与状态

- **表达**：`reuse a component`（复用组件）；`manage state`（管理状态）；`pass data to a child component`（向子组件传数据）
> [!example]
> We can reuse this component and keep the form state local.（我们可以复用这个组件，并把表单状态保留在本地。）
- **提示**：谈组件状态时的 `local` 指局部状态，不是本地开发环境。

### 用户交互

- **表达**：`handle a click`（处理点击）；`submit a form`（提交表单）；`show a loading state`（显示加载状态）
> [!example]
> Show a loading state while the form is being submitted.（表单提交期间显示加载状态。）

### 数据请求

- **表达**：`fetch data from the API`（从接口获取数据）；`cache the response`（缓存响应）；`handle an error response`（处理错误响应）
> [!example]
> The page fetches data from the API and handles an error response if the request fails.（页面从接口获取数据，并在请求失败时处理错误响应。）
- **提示**：`request` 是请求，`response` 是响应；不要把二者都笼统地叫 `interface`。

### 性能

- **表达**：`reduce bundle size`（减小打包体积）；`avoid unnecessary re-renders`（避免不必要的重复渲染）；`lazy-load images`（延迟加载图片）
> [!example]
> We lazy-load images below the fold to improve the initial load time.（我们对首屏以下的图片做延迟加载，以改善首次加载时间。）

### 可访问性与适配

- **表达**：`support keyboard navigation`（支持键盘导航）；`add an accessible label`（添加无障碍标签）；`work across screen sizes`（适配不同屏幕尺寸）
> [!example]
> The dialog should support keyboard navigation and work across screen sizes.（这个对话框应支持键盘导航，并适配不同屏幕尺寸。）

### 还原设计稿

- **表达**：`match the design`（与设计稿一致）；`follow the design spec`（按设计规范实现）；`The spacing looks off.`（间距看着不对）
> [!example]
> The mobile layout doesn't match the design yet. I still need to adjust the spacing.（移动端布局还没和设计稿对齐。我还需要调整间距。）

### 响应式布局

- **表达**：`responsive layout`（响应式布局）；`breakpoint`（断点）；`overflow on small screens`（小屏幕上溢出）
> [!example]
> The table overflows on small screens, so we need a different layout at that breakpoint.（表格在小屏幕上溢出，因此那个断点需要不同的布局。）

### 表单校验

- **表达**：`validate the input`（校验输入）；`show an inline error`（就地显示错误提示）；`disable the submit button`（禁用提交按钮）
> [!example]
> If the email is invalid, show an inline error instead of submitting the form.（邮箱无效时，在输入处显示错误提示，而不是提交表单。）

### 加载、空白与错误状态

- **表达**：`loading state`（加载状态）；`empty state`（空状态）；`error state`（错误状态）；`retry the request`（重试请求）
> [!example]
> The happy path works, but we still need an empty state and a way to retry after an error.（正常流程能用，但我们还需要空状态，以及出错后的重试方式。）
- **提示**：`happy path` 指一切按预期进行的主要流程，不涵盖异常情况。

### 路由与权限

- **表达**：`navigate to a page`（跳转到页面）；`redirect the user`（重定向用户）；`protect a route`（保护需要权限的路由）
> [!example]
> If the user isn't signed in, redirect them to the login page before they can open this route.（用户未登录时，先将其跳转到登录页，再允许访问这个路由。）

### 浏览器兼容

- **表达**：`browser compatibility`（浏览器兼容性）；`fall back to ...`（退回使用……）；`test in Safari`（在 Safari 中测试）
> [!example]
> This feature works in Chrome, but we still need to test it in Safari.（这个功能在 Chrome 中正常，但我们还需要在 Safari 中测试。）

### 性能问题的具体描述

- **表达**：`the initial load is slow`（首次加载慢）；`the page feels sluggish`（页面感觉卡顿）；`measure the impact`（衡量影响）
> [!example]
> The page feels sluggish when the list gets long. Let's measure the impact before changing the rendering strategy.（列表变长时页面感觉卡顿。调整渲染策略之前，先测量具体影响。）
