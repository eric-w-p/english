# 发布与线上问题

返回 [[程序员英语/README|程序员英语]]

### 发布与环境

- **表达**：`deploy to staging`（部署到预发布环境）；`deploy to production`（部署到生产环境）；`go live`（正式上线）
> [!example]
> We'll deploy to staging first and go live after QA signs off.（我们会先部署到预发布环境，测试团队确认通过后再正式上线。）
- **提示**：`deploy` 强调部署动作，`go live` 强调对用户正式开放。

### 逐步放量

- **表达**：`roll out the feature gradually`（逐步开放功能）；`enable the feature flag`（打开功能开关）
> [!example]
> Let's roll out the feature gradually and watch the error rate.（我们逐步开放这个功能，并关注错误率。）

### 上线验证

- **表达**：`run a smoke test`（做冒烟测试）；`monitor error rates`（监控错误率）；`check the dashboards`（查看监控面板）
> [!example]
> After deployment, we'll run a smoke test and monitor error rates.（部署后，我们会做冒烟测试并监控错误率。）

### 回滚与修复

- **表达**：`roll back the release`（回滚版本）；`ship a hotfix`（发布紧急修复）；`The fix is live.`（修复已上线）
> [!example]
> We rolled back the release because checkout was failing for some users.（由于部分用户无法结账，我们回滚了这次发布。）
- **提示**：`roll out` 是逐步发布；`roll back` 是回滚，方向相反。

### 事故沟通

- **表达**：`We're investigating the issue.`（我们正在排查问题）；`We've identified the cause.`（我们已经找到原因）；`The service has recovered.`（服务已恢复）
> [!example]
> We're investigating increased error rates after the release and will share an update shortly.（我们正在排查发布后错误率上升的问题，很快会同步进展。）
- **提示**：未查明原因前先同步已确认的现象与处理进度，避免把推测说成结论。

### 发布前检查

- **表达**：`release checklist`（发布检查清单）；`Are we good to deploy?`（可以部署了吗？）；`What's the rollback plan?`（回滚方案是什么？）
> [!example]
> Before we deploy, let's check the release checklist and confirm the rollback plan.（部署前，先检查发布清单并确认回滚方案。）

### 预告发布

- **表达**：`We're planning to deploy ...`（我们计划部署……）；`The release is scheduled for ...`（发布定在……）；`expect brief downtime`（预计会短暂停机）
> [!example]
> We're planning to deploy the new search feature this afternoon. We don't expect downtime.（我们计划今天下午部署新的搜索功能；预计不会停机。）

### 发布过程中

- **表达**：`The deployment is in progress.`（部署正在进行）；`The deployment has completed.`（部署已完成）；`The release is paused.`（发布已暂停）
> [!example]
> The deployment has completed, but we'll keep monitoring before enabling the feature flag.（部署已完成，但打开功能开关前我们会继续监控。）

### 发现异常

- **表达**：`Error rates are climbing.`（错误率在上升）；`We're seeing a spike in ...`（我们发现……激增）；`This appears to affect ...`（这似乎影响……）
> [!example]
> We're seeing a spike in checkout errors after the release. This appears to affect mobile users.（发布后结账错误激增，目前看来影响移动端用户。）

### 缓解影响

- **表达**：`disable the feature flag`（关闭功能开关）；`mitigate the impact`（减轻影响）；`restore service`（恢复服务）
> [!example]
> We've disabled the feature flag to mitigate the impact while we investigate.（排查期间，我们已关闭功能开关以减轻影响。）
- **提示**：`mitigate` 是缓解影响，不一定表示已经修好根因。

### 沟通影响与恢复

- **表达**：`affected users`（受影响用户）；`The issue is resolved.`（问题已解决）；`We're monitoring for recurrence.`（我们正监控是否复发）
> [!example]
> The issue is resolved, and we're monitoring for recurrence. We'll share a fuller update after the review.（问题已解决，我们正监控是否复发；复盘后会提供更完整的说明。）

### 事故复盘

- **表达**：`postmortem`（事故复盘）；`timeline of events`（事件时间线）；`action items`（后续改进事项）
> [!example]
> The postmortem will cover the timeline, user impact, root cause, and action items.（复盘会涵盖时间线、用户影响、根因和后续改进事项。）

### 区分部署与发布

- **表达**：`The code is deployed but not enabled.`（代码已部署但尚未启用）；`roll out to a small group`（先向一小部分用户开放）
> [!example]
> The code is deployed, but the feature is only enabled for a small group of users.（代码已经部署，但功能只对少量用户开放。）
- **提示**：代码部署到生产环境不一定等于功能已经对所有用户开放。
