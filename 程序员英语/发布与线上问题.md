# 发布与线上问题

返回 [[程序员英语/README|程序员英语]]

### 发布与环境

- **表达**：`deploy to staging`（部署到预发布环境）；`deploy to production`（部署到生产环境）；`go live`（正式上线）
- **例句**：We'll deploy to staging first, then deploy to production after QA signs off.（我们会先部署到预发布环境，测试团队确认通过后再部署到生产环境。）
- **例句**：The feature will go live once the flag is enabled.（打开功能开关后，这个功能才会正式上线。）
- **提示**：`deploy` 强调部署动作，`go live` 强调对用户正式开放。

### 逐步放量

- **表达**：`roll out gradually`（逐步开放）；`enable the feature flag`（打开功能开关）；`watch the error rate`（关注错误率）
- **例句**：Let's enable the feature flag for a small group first.（先对一小部分用户打开功能开关。）
- **例句**：We'll roll out the feature gradually and watch the error rate.（我们会逐步开放功能，并关注错误率。）

### 上线验证

- **表达**：`run a smoke test`（做冒烟测试）；`monitor error rates`（监控错误率）；`check the dashboards`（查看监控面板）
- **例句**：After deployment, we'll run a smoke test on the checkout flow.（部署后，我们会对结账流程做冒烟测试。）
- **例句**：Let's check the dashboards and monitor error rates for the next hour.（接下来一小时，我们查看监控面板并关注错误率。）

### 回滚与修复

- **表达**：`roll back the release`（回滚版本）；`ship a hotfix`（发布紧急修复）；`the fix is live`（修复已上线）
- **例句**：We rolled back the release because checkout was failing for some users.（由于部分用户无法结账，我们回滚了这次发布。）
- **例句**：We shipped a hotfix, and the fix is now live.（我们发布了紧急修复，修复现已上线。）
- **提示**：`roll out` 是逐步发布；`roll back` 是回滚。

### 事故沟通

- **表达**：`investigate the issue`（排查问题）；`identify the cause`（找到原因）；`service has recovered`（服务已恢复）
- **例句**：We're investigating increased error rates after the release.（我们正在排查发布后错误率上升的问题。）
- **例句**：We've identified the cause, and the service has recovered.（我们已找到原因，服务也已恢复。）
- **提示**：未查明原因前，先同步已确认的现象和处理进度。

### 发布前检查

- **表达**：`release checklist`（发布检查清单）；`good to deploy`（可以部署）；`rollback plan`（回滚方案）
- **例句**：Before we deploy, let's go through the release checklist.（部署前，先过一下发布清单。）
- **例句**：Are we good to deploy, and what's the rollback plan if something goes wrong?（可以部署了吗？如果出问题，回滚方案是什么？）

### 预告发布

- **表达**：`plan to deploy`（计划部署）；`scheduled release`（计划中的发布）；`expect downtime`（预计停机）
- **例句**：We're planning to deploy the new search feature this afternoon.（我们计划今天下午部署新的搜索功能。）
- **例句**：The release is scheduled for the evening, and we don't expect downtime.（发布安排在晚上，预计不会停机。）

### 发布过程中

- **表达**：`deployment in progress`（部署正在进行）；`deployment completed`（部署已完成）；`release paused`（发布已暂停）
- **例句**：The deployment is in progress; please hold off on merging new changes.（部署正在进行，请先不要合并新的改动。）
- **例句**：The deployment has completed, but the release is paused while we check the metrics.（部署已完成，但我们查看指标期间暂停发布。）

### 发现异常

- **表达**：`error rates are climbing`（错误率在上升）；`a spike in errors`（错误激增）；`appear to affect`（似乎影响）
- **例句**：Error rates are climbing after the release.（发布后错误率在上升。）
- **例句**：We're seeing a spike in checkout errors. This appears to affect mobile users.（结账错误激增，目前看来影响移动端用户。）

### 缓解影响

- **表达**：`disable the feature flag`（关闭功能开关）；`mitigate the impact`（减轻影响）；`restore service`（恢复服务）
- **例句**：We've disabled the feature flag to mitigate the impact while we investigate.（排查期间，我们已关闭功能开关以减轻影响。）
- **例句**：Rolling back the release should restore service for affected users.（回滚版本应该能为受影响用户恢复服务。）
- **提示**：`mitigate` 表示缓解影响，不一定已解决根因。

### 沟通影响与恢复

- **表达**：`affected users`（受影响用户）；`issue resolved`（问题已解决）；`monitor for recurrence`（监控是否复发）
- **例句**：We've contacted the affected users and explained what happened.（我们已联系受影响的用户并解释情况。）
- **例句**：The issue is resolved, and we're monitoring for recurrence.（问题已解决，我们正监控是否复发。）

### 事故复盘

- **表达**：`postmortem`（事故复盘）；`timeline of events`（事件时间线）；`action items`（后续改进事项）
- **例句**：We'll write a postmortem once the service is stable.（服务稳定后，我们会写事故复盘。）
- **例句**：The postmortem will cover the timeline of events, user impact, root cause, and action items.（复盘会涵盖事件时间线、用户影响、根因和后续改进事项。）

### 区分部署与发布

- **表达**：`deployed but not enabled`（已部署但尚未启用）；`roll out to a small group`（先向一小部分用户开放）
- **例句**：The code is deployed, but the feature isn't enabled for everyone yet.（代码已经部署，但功能还没有对所有用户开放。）
- **例句**：We'll roll it out to a small group before making it available to everyone.（我们会先向一小部分用户开放，再面向所有用户。）
