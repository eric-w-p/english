# 测试与接口联调

返回 [[程序员英语/README|程序员英语]]

### 测试类型

- **表达**：`unit test`（单元测试）；`integration test`（集成测试）；`end-to-end test` / `E2E test`（端到端测试）
> [!example]
> We have unit tests for the validation logic and an end-to-end test for checkout.（我们为校验逻辑写了单元测试，也为结账流程写了端到端测试。）
- **提示**：`integration test` 检查部分模块如何一起工作；`E2E` 更关注完整用户流程。

### 测试边界情况

- **表达**：`cover edge cases`（覆盖边界情况）；`test the empty state`（测试空状态）；`test the failure path`（测试失败路径）
> [!example]
> Let's test the empty state and the failure path before we hand this over to QA.（交给测试团队之前，先测一下空状态和失败路径。）

### 核对接口契约

- **表达**：`agree on the API contract`（对齐接口契约）；`request payload`（请求体）；`response format`（响应格式）
> [!example]
> Can we agree on the response format before frontend and backend start working in parallel?（前后端并行开发前，我们能先确定响应格式吗？）
- **提示**：口语里“前后端联调”常具体说 `integrate the frontend with the backend` 或 `test the API integration`，不必直译成 `joint debugging`。

### 排查接口不一致

- **表达**：`The field is missing from the response.`（响应里缺少这个字段）；`The endpoint returns a 404.`（这个接口端点返回 404）；`The data doesn't match the spec.`（数据与文档不符）
> [!example]
> The endpoint returns a 404 in staging, but it works locally.（这个接口在预发布环境返回 404，本地却正常。）

### 验收

- **表达**：`acceptance criteria`（验收标准）；`sign off on the feature`（确认功能可以验收／放行）
> [!example]
> The feature meets the acceptance criteria. Can QA sign off on it?（功能已符合验收标准。测试团队可以确认通过吗？）

### 约定字段与类型

- **表达**：`required field`（必填字段）；`optional field`（可选字段）；`The field can be null.`（这个字段可能为 null）
> [!example]
> Is `avatarUrl` optional, or will the API always return it?（`avatarUrl` 是可选字段，还是接口总会返回它？）

### 对齐错误码

- **表达**：`status code`（状态码）；`error message`（错误信息）；`How should we handle a 401?`（遇到 401 应如何处理？）
> [!example]
> What status code will the API return when the session expires?（会话过期时接口会返回什么状态码？）

### 模拟数据与真实接口

- **表达**：`mock the API response`（模拟接口响应）；`switch to the real endpoint`（切换到真实接口）；`the mock data is out of date`（模拟数据已过时）
> [!example]
> The UI works with mock data, but the real response has a different field name.（界面使用模拟数据时正常，但真实响应的字段名不同。）

### 环境配置

- **表达**：`environment variable`（环境变量）；`point to the staging API`（指向预发布接口）；`use the wrong base URL`（使用了错误的基础地址）
> [!example]
> The request is going to production because the staging base URL isn't set.（请求发到了生产环境，因为预发布的基础地址没有配置。）

### 测试数据与账号

- **表达**：`test account`（测试账号）；`seed the database`（初始化测试数据）；`reset the test data`（重置测试数据）
> [!example]
> Do we have a test account with permission to view this page?（有可以查看此页面的测试账号吗？）

### 复现测试失败

- **表达**：`The test is failing.`（测试失败）；`flaky test`（偶发失败的测试）；`run the test locally`（在本地运行测试）
> [!example]
> The test passes locally but fails intermittently in CI. It might be flaky.（这个测试在本地通过，但在 CI 中偶发失败；它可能不稳定。）
- **提示**：不要把稳定失败的测试称作 `flaky`；先确认是否与时序或环境有关。

### 交给测试团队

- **表达**：`ready for QA`（可以交测）；`known issue`（已知问题）；`test on multiple devices`（在多种设备上测试）
> [!example]
> The feature is ready for QA. The only known issue is a layout problem on smaller screens.（功能可以交测了。唯一已知问题是小屏幕上的布局问题。）
