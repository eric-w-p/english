# 测试与接口联调

返回 [[程序员英语/README|程序员英语]]

### 测试类型

- **表达**：`unit test`（单元测试）；`integration test`（集成测试）；`end-to-end test` / `E2E test`（端到端测试）
- **例句**：We have unit tests for the validation logic.（我们为校验逻辑写了单元测试。）
- **例句**：The integration test checks the API response, while the end-to-end test covers the checkout flow.（集成测试检查接口响应，端到端测试覆盖结账流程。）

### 测试边界情况

- **表达**：`cover edge cases`（覆盖边界情况）；`test the empty state`（测试空状态）；`test the failure path`（测试失败路径）
- **例句**：The current tests cover the main flow, but not the edge cases.（当前测试覆盖了主要流程，但没覆盖边界情况。）
- **例句**：Let's test the empty state and the failure path before we hand this over to QA.（交给测试团队之前，先测一下空状态和失败路径。）

### 核对接口契约

- **表达**：`agree on the API contract`（对齐接口契约）；`request payload`（请求体）；`response format`（响应格式）
- **例句**：Can we agree on the API contract before frontend and backend start working in parallel?（前后端并行开发前，我们能先对齐接口契约吗？）
- **例句**：The request payload looks right, but the response format doesn't match the spec.（请求体看着没问题，但响应格式和文档不符。）
- **提示**：“前后端联调”可说 `integrate the frontend with the backend` 或 `test the API integration`。

### 排查接口不一致

- **表达**：`missing from the response`（响应里缺失）；`return a 404`（返回 404）；`not match the spec`（与文档不符）
- **例句**：The `status` field is missing from the response.（响应里缺少 `status` 字段。）
- **例句**：The endpoint returns a 404 in staging, and the data doesn't match the spec locally.（这个端点在预发布环境返回 404，本地数据也与文档不符。）

### 验收

- **表达**：`acceptance criteria`（验收标准）；`sign off on the feature`（确认功能通过验收）
- **例句**：The feature meets the acceptance criteria. Can QA sign off on it?（功能已符合验收标准。测试团队可以确认通过吗？）

### 约定字段与类型

- **表达**：`required field`（必填字段）；`optional field`（可选字段）；`can be null`（可能为 null）
- **例句**：Is `avatarUrl` a required field or an optional field?（`avatarUrl` 是必填字段还是可选字段？）
- **例句**：Can the `avatarUrl` field be null?（`avatarUrl` 字段可能是 null 吗？）

### 对齐错误码

- **表达**：`status code`（状态码）；`error message`（错误信息）；`handle a 401`（处理 401）
- **例句**：What status code will the API return when the session expires?（会话过期时接口会返回什么状态码？）
- **例句**：How should we handle a 401, and which error message should we show?（遇到 401 应如何处理？该显示什么错误信息？）

### 模拟数据与真实接口

- **表达**：`mock the API response`（模拟接口响应）；`switch to the real endpoint`（切换到真实接口）；`out-of-date mock data`（过时的模拟数据）
- **例句**：We mocked the API response while the endpoint was being built.（端点开发期间，我们模拟了接口响应。）
- **例句**：After switching to the real endpoint, we found that the mock data was out of date.（切换到真实接口后，我们发现模拟数据已经过时。）

### 环境配置

- **表达**：`environment variable`（环境变量）；`point to the staging API`（指向预发布接口）；`base URL`（基础地址）
- **例句**：The environment variable should point to the staging API.（这个环境变量应指向预发布接口。）
- **例句**：The request is going to production because the staging base URL isn't set.（请求发到了生产环境，因为预发布的基础地址没有配置。）

### 测试数据与账号

- **表达**：`test account`（测试账号）；`seed the database`（初始化测试数据）；`reset the test data`（重置测试数据）
- **例句**：Do we have a test account with permission to view this page?（有可以查看此页面的测试账号吗？）
- **例句**：We can seed the database before the test and reset the test data afterward.（可以在测试前初始化数据库，测试后重置数据。）

### 复现测试失败

- **表达**：`test fails locally`（本地测试失败）；`flaky test`（偶发失败的测试）；`fail intermittently in CI`（在 CI 中偶发失败）
- **例句**：The test fails locally whenever the date is missing.（缺少日期时，这个测试在本地每次都会失败。）
- **例句**：It passes locally but fails intermittently in CI. It might be a flaky test.（它在本地通过，但在 CI 中偶发失败；可能是个不稳定的测试。）

### 交给测试团队

- **表达**：`ready for QA`（可以交测）；`known issue`（已知问题）；`test on multiple devices`（在多种设备上测试）
- **例句**：The feature is ready for QA. The only known issue is a layout problem on smaller screens.（功能可以交测了。唯一已知问题是小屏幕上的布局问题。）
- **例句**：Could you test it on multiple devices?（能在多种设备上测试一下吗？）
