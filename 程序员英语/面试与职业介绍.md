# 面试与职业介绍

返回 [[程序员英语/README|程序员英语]]

### 介绍职责

- **表达**：`I'm a frontend developer.`（我是前端开发工程师）；`I work mainly on ...`（我主要负责……）；`I collaborate with designers and backend engineers.`（我与设计师和后端工程师协作）
> [!example]
> I work mainly on user-facing features and collaborate with designers and backend engineers.（我主要负责面向用户的功能，并与设计师和后端工程师协作。）
- **提示**：介绍职责时，`work on` 比逐项罗列技术栈更容易展开具体项目。

### 讲项目贡献

- **表达**：`I was responsible for ...`（我负责……）；`I implemented ...`（我实现了……）；`I improved ... by ...`（我通过……改进了……）
> [!example]
> I implemented the checkout flow and improved its loading time by reducing unnecessary requests.（我实现了结账流程，并通过减少不必要的请求缩短了加载时间。）
- **提示**：面试中区分个人贡献和团队成果；没有可靠数据时，不编造提升百分比。

### 解释技术选择

- **表达**：`We chose A over B because ...`（我们选择 A 而不是 B，因为……）；`The main trade-off was ...`（主要取舍是……）
> [!example]
> We chose a simpler approach because the feature had a tight deadline. The main trade-off was less flexibility.（由于这个功能期限紧，我们选择了更简单的方案；主要代价是灵活性较低。）
- **提示**：`trade-off` 指得失之间的取舍，不等于单纯的缺点。

### 讲困难与反思

- **表达**：`The biggest challenge was ...`（最大的挑战是……）；`Looking back, I would ...`（现在回头看，我会……）
> [!example]
> The biggest challenge was handling inconsistent API responses. Looking back, I would agree on the response format earlier.（最大的挑战是处理不一致的接口响应。现在回头看，我会更早敲定响应格式。）

### 向面试官提问

- **表达**：`How is the team structured?`（团队如何分工？）；`What would success look like in this role?`（这个岗位做得好是什么样？）
> [!example]
> How do frontend and backend engineers usually coordinate on new features?（前后端工程师通常如何协作开发新功能？）

### 概括技术经验

- **表达**：`I've worked with ...`（我用过……）；`I'm most comfortable with ...`（我最熟悉……）；`I have some exposure to ...`（我接触过……）
> [!example]
> I'm most comfortable with frontend development, and I have some exposure to backend APIs.（我最熟悉前端开发，也接触过后端接口。）
- **提示**：`have some exposure to` 适合如实描述接触过但不精通的技术。

### 介绍项目背景

- **表达**：`The project was aimed at ...`（这个项目旨在……）；`The team consisted of ...`（团队由……组成）；`My part was ...`（我负责的部分是……）
> [!example]
> The project was aimed at simplifying checkout. My part was the frontend flow and API integration.（项目旨在简化结账流程。我负责前端流程和接口联调。）

### 回答为什么换工作

- **表达**：`I'm looking for ...`（我希望寻找……）；`I'd like to take on more ...`（我想承担更多……）；`I'm interested in this role because ...`（我对这个岗位感兴趣，因为……）
> [!example]
> I'm looking for a role where I can take on more ownership of features from design to release.（我希望找到一个能从设计到上线更完整地负责功能的岗位。）
- **提示**：面试中更自然的是谈下一步目标，不必只讲对上一份工作的不满。

### 回答不熟悉的问题

- **表达**：`I haven't used that in production.`（我还没在生产环境用过它）；`My understanding is ...`（我的理解是……）；`I'd start by ...`（我会先……）
> [!example]
> I haven't used that in production, but my understanding is that it helps with caching. I'd start by checking the requirements.（我还没在生产环境用过它，但我的理解是它有助于缓存。我会先确认需求。）

### 解释排错过程

- **表达**：`First, I reproduced the issue.`（首先我复现了问题）；`Then I ruled out ...`（接着我排除了……）；`Finally, I verified ...`（最后我验证了……）
> [!example]
> First, I reproduced the issue. Then I ruled out the API response and traced it to stale UI state.（我先复现问题，再排除接口响应，最后定位到过期的界面状态。）

### 回答合作冲突

- **表达**：`We had different views on ...`（我们对……有不同看法）；`We agreed on ...`（我们最终就……达成一致）；`I learned to ...`（我学会了……）
> [!example]
> We had different views on the implementation, so we compared the trade-offs and agreed on the simpler option.（我们对实现方式有不同看法，于是比较了取舍，最终选择了更简单的方案。）

### 讨论成长与反馈

- **表达**：`I asked for feedback on ...`（我就……征求反馈）；`I took ownership of ...`（我主动负责……）；`I'm working on improving ...`（我正在提升……）
> [!example]
> I'm working on improving how I communicate risks early in a project.（我正在提升自己在项目早期沟通风险的能力。）
