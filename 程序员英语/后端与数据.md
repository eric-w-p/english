# 后端与数据

返回 [[程序员英语/README|程序员英语]]

### 设计接口

- **表达**：`expose an endpoint`（提供接口端点）；`validate the input`（校验输入）；`return a response`（返回响应）
- **例句**：The service exposes an endpoint for user profiles.（这个服务提供一个查询用户资料的接口端点。）
- **例句**：It validates the input before returning a response.（它在返回响应前会校验输入。）

### 查询与存储

- **表达**：`query the database`（查询数据库）；`add an index`（添加索引）；`store a record`（存储记录）
- **例句**：The service queries the database before returning the list.（这个服务先查询数据库，再返回列表。）
- **例句**：We added an index to speed up the query and store each new record in the same table.（我们添加了索引来加快查询，并把每条新记录存入同一张表。）

### 数据一致性

- **表达**：`update a record`（更新记录）；`run a migration`（执行数据库迁移）；`keep the data consistent`（保持数据一致）
- **例句**：We need to run a migration before updating records with the new field.（用新字段更新记录前，我们需要执行数据库迁移。）
- **例句**：Both operations should succeed together to keep the data consistent.（这两个操作应该一起成功，以保持数据一致。）

### 异步处理

- **表达**：`queue a job`（将任务放入队列）；`process it in the background`（在后台处理）；`retry a failed job`（重试失败任务）
- **例句**：We queue the report generation job and process it in the background.（我们把报告生成任务加入队列，在后台处理。）
- **例句**：If a job fails, the worker retries it.（如果任务失败，工作进程会重试。）
- **提示**：这里的 `job` 指后台任务，不是工作岗位。

### 分页与筛选

- **表达**：`paginate the results`（对结果分页）；`filter by status`（按状态筛选）；`sort by creation date`（按创建时间排序）
- **例句**：The endpoint paginates the results and lets clients filter by status.（这个接口对结果分页，并允许客户端按状态筛选。）
- **例句**：Can we sort the results by creation date, newest first?（能按创建时间排序，把最新的放前面吗？）

### 修改接口

- **表达**：`add a field to the response`（在响应里增加字段）；`breaking change`（不兼容变更）；`backward compatibility`（向后兼容）
- **例句**：We can add a field to the response without changing existing fields.（我们可以在不修改现有字段的情况下，给响应增加字段。）
- **例句**：Removing this field would be a breaking change, so we need to maintain backward compatibility.（删除这个字段会造成不兼容变更，因此需要保持向后兼容。）

### 数据库事务

- **表达**：`start a transaction`（开启事务）；`commit the transaction`（提交事务）；`roll it back`（回滚事务）
- **例句**：Start a transaction before updating the order and the payment record.（更新订单和支付记录前，先开启事务。）
- **例句**：If both updates succeed, commit the transaction. Otherwise, roll it back.（如果两个更新都成功，就提交事务；否则回滚。）

### 缓存与过期

- **表达**：`cache the result`（缓存结果）；`invalidate the cache`（使缓存失效）；`stale data`（过期数据）
- **例句**：We cache the result to avoid querying the database on every request.（我们缓存结果，避免每次请求都查数据库。）
- **例句**：The page shows stale data because the cache isn't invalidated after the update.（页面显示旧数据，因为更新后缓存没有失效。）

### 超时与重试

- **表达**：`set a timeout`（设置超时）；`retry the request`（重试请求）；`avoid duplicate processing`（避免重复处理）
- **例句**：Set a timeout so the request doesn't wait indefinitely.（设置超时，避免请求无限等待。）
- **例句**：If the request times out, a retry must avoid duplicate processing and must not create a second order.（请求超时后，重试要避免重复处理，不能创建第二笔订单。）

### 日志与追踪

- **表达**：`log the error`（记录错误日志）；`trace a request across services`（跨服务追踪请求）；`request ID`（请求标识符）
- **例句**：Log the error with the request ID so we can find it later.（把请求 ID 和错误一起记入日志，方便之后查找。）
- **例句**：Could you share the request ID so I can trace the request across services?（能提供请求 ID 吗？我好跨服务追踪这次请求。）

### 数据修复

- **表达**：`backfill missing data`（回填缺失数据）；`check affected records`（检查受影响的记录）；`verify the migration`（验证迁移结果）
- **例句**：After the migration, we'll backfill missing data.（迁移之后，我们会回填缺失数据。）
- **例句**：Let's check the affected records and verify the migration before enabling the new field.（启用新字段前，检查受影响的记录并验证迁移结果。）
