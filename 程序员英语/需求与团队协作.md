# 需求与团队协作

返回 [[程序员英语/README|程序员英语]]

### 澄清需求

- **表达**：`Could you clarify ...?`（能说明一下……吗？）；`What's the expected behavior when ...?`（……时预期行为是什么？）；`Is this in scope?`（这在本次范围内吗？）
> [!example]
> Could you clarify what should happen when the user loses their connection?（能说明用户断网时应如何处理吗？）
- **提示**：`scope` 指当前任务或版本的范围；`out of scope` 是不在范围内。

### 对齐优先级与时间

- **表达**：`What's the priority for this?`（这件事优先级如何？）；`I can have a first version ready by ...`（我可以在……前完成初版）；`This depends on ...`（这取决于……）
> [!example]
> I can have a first version ready by Friday, but the final estimate depends on the API design.（我可以在周五前完成初版，但最终工期取决于接口设计。）
- **提示**：`estimate` 是估算，不是承诺；还不确定时说清依赖条件。

### 同步进度

- **表达**：`I've finished ... and I'm working on ...`（我已完成……，正在处理……）；`I'm blocked by ...`（我被……卡住了）
> [!example]
> I've finished the form UI, and I'm working on validation. I'm blocked by a missing API field.（表单界面已完成，我正在做校验；目前被缺失的接口字段卡住了。）

### 协商变更

- **表达**：`Can we revisit this requirement?`（我们能重新讨论这个需求吗？）；`This change may affect ...`（这个变更可能影响……）
> [!example]
> This change may affect the release date. Can we agree on the must-have behavior first?（这个变更可能影响发布日期。我们能先确定必须实现的行为吗？）
- **提示**：`must-have` 是必须有的内容；`nice-to-have` 是有更好但非必需。

### 异步协作

- **表达**：`I'll leave a comment on the ticket.`（我会在任务单里留言）；`Could you take a look when you have a chance?`（方便时能看一下吗？）
> [!example]
> I'll leave the open questions on the ticket so we can track the decisions.（我会把待确认的问题留在任务单里，方便追踪决定。）

### 站会与今日计划

- **表达**：`Yesterday I worked on ...`（昨天我做了……）；`Today I'll focus on ...`（今天我会重点做……）；`I don't have any blockers.`（目前没有阻塞）
> [!example]
> Yesterday I finished the search UI. Today I'll wire it up to the API. I don't have any blockers.（昨天我完成了搜索界面。今天会接上接口，目前没有阻塞。）
- **提示**：站会里 `blocker` 是阻碍推进的问题，不是所有小问题都需要说成 blocker。

### 确认验收标准

- **表达**：`What are the acceptance criteria?`（验收标准是什么？）；`Does this include mobile?`（这包括移动端吗？）；`Can we define the edge cases?`（能确定边界情况吗？）
> [!example]
> Does this include mobile, and what should the empty state look like?（这包括移动端吗？空状态应该是什么样？）

### 拆分任务

- **表达**：`break this down into smaller tasks`（把它拆成小任务）；`pick up a ticket`（接手一张任务单）；`hand this off to ...`（把这件事移交给……）
> [!example]
> Let's break this down into the UI, API integration, and testing. I can pick up the UI ticket.（我们把它拆成界面、接口联调和测试。我可以接界面的任务单。）
- **提示**：`pick up` 在工作语境里常指“接手”，不是“捡起”。

### 请求设计或产品确认

- **表达**：`Can you confirm the intended behavior?`（能确认预期行为吗？）；`Do we have the latest design?`（有最新版设计稿吗？）；`Which version should we follow?`（该以哪个版本为准？）
> [!example]
> The ticket and the design show different error messages. Which version should we follow?（任务单和设计稿里的错误提示不一样。我们该以哪个为准？）

### 提醒依赖与风险

- **表达**：`We're waiting on ...`（我们在等……）；`This is a dependency for ...`（这是……的前置依赖）；`This may put the timeline at risk.`（这可能影响时间安排）
> [!example]
> We're waiting on the API schema. If it changes again, this may put the timeline at risk.（我们在等接口结构。如果它再次变化，工期可能受影响。）
- **提示**：`waiting on` 在口语中常见；更正式也可说 `waiting for`。

### 主动请求帮助

- **表达**：`Could we pair on this?`（我们能一起排查／结对做吗？）；`I could use another pair of eyes.`（我想请人帮忙再看一眼）；`Do you have a few minutes to sync?`（有几分钟可以对一下吗？）
> [!example]
> I've been looking at this rendering issue for a while. Could we pair on it for ten minutes?（这个渲染问题我查了一阵子了。我们能一起看十分钟吗？）

### 会议结论与跟进

- **表达**：`To recap, ...`（总结一下……）；`The next step is ...`（下一步是……）；`I'll follow up with ...`（我会跟进……）
> [!example]
> To recap, we'll keep the current design for this release. I'll follow up with QA on the test cases.（总结一下，这次发布沿用当前设计。我会跟测试团队跟进测试用例。）
