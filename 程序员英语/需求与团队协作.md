# 需求与团队协作

返回 [[程序员英语/README|程序员英语]]

### 澄清需求

- **表达**：`clarify the requirement`（澄清需求）；`expected behavior`（预期行为）；`in scope`（在本次范围内）
- **例句**：Could you clarify what should happen when the user loses their connection?（能说明用户断网时应如何处理吗？）
- **例句**：What's the expected behavior if the request fails?（请求失败时预期行为是什么？）
- **例句**：Is the mobile layout in scope for this release?（移动端布局在这次发布范围内吗？）
- **提示**：`out of scope` 表示不在当前任务范围内。

### 对齐优先级与时间

- **表达**：`priority`（优先级）；`a first version`（初版）；`depend on`（取决于）
- **例句**：What's the priority for this compared with the login bug?（和登录问题相比，这件事的优先级如何？）
- **例句**：I can have a first version ready by Friday, but the final estimate depends on the API design.（我可以在周五前完成初版，但最终工期取决于接口设计。）
- **提示**：`estimate` 是估算，不是承诺；不确定时说清依赖条件。

### 同步进度

- **表达**：`finish the UI`（完成界面）；`work on validation`（处理校验）；`be blocked by`（因某个问题受阻）
- **例句**：I've finished the form UI, and I'm working on validation.（表单界面已完成，我正在做校验。）
- **例句**：I'm blocked by a missing field in the API response.（接口响应中缺了一个字段，卡住了我。）

### 协商变更

- **表达**：`revisit a requirement`（重新讨论需求）；`affect the release date`（影响发布日期）；`must-have behavior`（必须实现的行为）
- **例句**：Can we revisit the requirement for guest checkout?（我们能重新讨论游客结账的需求吗？）
- **例句**：This change may affect the release date. Can we agree on the must-have behavior first?（这个变更可能影响发布日期。我们能先确定必须实现的行为吗？）
- **提示**：`nice-to-have` 指有更好但非必需的内容。

### 异步协作

- **表达**：`leave a comment on the ticket`（在任务单留言）；`take a look`（看一下）；`track the decision`（追踪决定）
- **例句**：I'll leave the open questions on the ticket so we can track the decisions.（我会把待确认的问题留在任务单里，方便追踪决定。）
- **例句**：Could you take a look at my comment when you have a chance?（方便时能看一下我留的评论吗？）

### 站会与今日计划

- **表达**：`finish the search UI`（完成搜索界面）；`wire it up to the API`（把它接上接口）；`blocker`（阻碍推进的问题）
- **例句**：Yesterday I finished the search UI. Today I'll wire it up to the API.（昨天我完成了搜索界面。今天会接上接口。）
- **例句**：I don't have any blockers right now.（目前没有阻塞。）
- **提示**：不是所有小问题都需要说成 `blocker`。

### 确认验收标准

- **表达**：`acceptance criteria`（验收标准）；`include mobile`（包括移动端）；`edge cases`（边界情况）
- **例句**：What are the acceptance criteria for the search feature?（搜索功能的验收标准是什么？）
- **例句**：Does this include mobile, and can we define the edge cases?（这包括移动端吗？我们能确定边界情况吗？）

### 拆分任务

- **表达**：`break this down`（拆分这件事）；`pick up a ticket`（接手任务单）；`hand off`（移交）
- **例句**：Let's break this down into the UI, API integration, and testing.（我们把它拆成界面、接口联调和测试。）
- **例句**：I can pick up the UI ticket and hand off the API questions to the backend team.（我可以接界面任务，并把接口问题转给后端团队。）

### 请求设计或产品确认

- **表达**：`intended behavior`（预期行为）；`the latest design`（最新版设计稿）；`follow the design`（以设计稿为准）
- **例句**：Can you confirm the intended behavior when there are no results?（没有结果时应如何处理，能确认一下吗？）
- **例句**：Do we have the latest design? The ticket and the design show different error messages.（有最新版设计稿吗？任务单和设计稿里的错误提示不一样。）
- **例句**：Which version should we follow?（我们该以哪个版本为准？）

### 提醒依赖与风险

- **表达**：`wait on the API schema`（等待接口结构）；`a dependency for`（另一项工作的前置依赖）；`put the timeline at risk`（影响时间安排）
- **例句**：We're waiting on the API schema; it's a dependency for the frontend integration.（我们在等接口结构，这是前端联调的前置条件。）
- **例句**：If it changes again, this may put the timeline at risk.（如果它再次变化，工期可能受影响。）

### 主动请求帮助

- **表达**：`pair on a problem`（结对排查问题）；`another pair of eyes`（请别人再看一眼）；`sync`（简短对齐）
- **例句**：I've been looking at this rendering issue for a while. Could we pair on it for ten minutes?（这个渲染问题我查了一阵子了。我们能一起看十分钟吗？）
- **例句**：I could use another pair of eyes. Do you have a few minutes to sync?（我想请人帮忙再看一眼。你有几分钟能对一下吗？）

### 会议结论与跟进

- **表达**：`to recap`（总结一下）；`the next step`（下一步）；`follow up with QA`（与测试团队跟进）
- **例句**：To recap, we'll keep the current design for this release.（总结一下，这次发布沿用当前设计。）
- **例句**：The next step is to confirm the error states with the designer.（下一步是和设计师确认错误状态。）
- **例句**：I'll follow up with QA on the test cases.（我会跟测试团队跟进测试用例。）
