# 代码评审与版本管理

返回 [[程序员英语/README|程序员英语]]

### 提交与分支

- **表达**：`create a branch`（创建分支）；`commit the changes`（提交改动）；`push the branch`（推送分支）
- **例句**：I'll create a branch for the fix.（我会为这个修复创建分支。）
- **例句**：I'll commit the changes and push the branch after the tests pass.（测试通过后，我会提交改动并推送分支。）
- **提示**：`commit` 是提交到版本库，`push` 是推送到远端。

### 发起评审

- **表达**：`open a PR`（发起拉取请求）；`request a review`（请求评审）；`add a search filter`（添加搜索筛选）
- **例句**：I've opened a PR that adds a search filter.（我为新增搜索筛选发了 PR。）
- **例句**：Could I request a review from you?（能请你评审一下吗？）

### 给出具体反馈

- **表达**：`simplify this`（简化这里）；`handle request failure`（处理请求失败）；`nit`（非阻塞的小建议）
- **例句**：Could we simplify this condition?（这个条件判断能简化吗？）
- **例句**：What happens if the request fails? Could we show an error message?（如果请求失败会怎样？能显示错误提示吗？）
- **例句**：Nit: Could we rename this variable for clarity?（小建议：这个变量能换个更清楚的名字吗？）
- **提示**：必须修复的问题不要标成 `nit`。

### 回复评审意见

- **表达**：`Good catch.`（发现得好）；`address the comments`（处理评审意见）；`leave a reply`（补充回复）
- **例句**：Good catch. I've added a test for that case.（发现得好。我已经为那个情况加了测试。）
- **例句**：I've addressed your comments and left a reply with more context.（我已处理你的评审意见，并回复补充了背景。）

### 合并冲突

- **表达**：`resolve a merge conflict`（解决合并冲突）；`merge the PR`（合并 PR）
- **例句**：I need to resolve a merge conflict before we can merge the PR.（合并这个 PR 前，我需要先解决合并冲突。）

### 写清 PR 内容

- **表达**：`summary of changes`（改动摘要）；`how to test`（测试方法）；`screenshots of the UI`（界面截图）
- **例句**：I added a summary of changes and a "How to test" section to the PR description.（我在 PR 描述里补充了改动摘要和测试方法。）
- **例句**：I've also attached screenshots of the UI.（我还附上了界面截图。）

### 标记未完成的工作

- **表达**：`draft PR`（草稿 PR）；`work in progress` / `WIP`（仍在进行中）；`ready for review`（可以评审）
- **例句**：I've opened a draft PR because the tests are still a work in progress.（测试还在写，所以我先开了一个草稿 PR。）
- **例句**：The PR is ready for review now, but not ready to merge until CI passes.（PR 现在可以评审了，但要等 CI 通过才能合并。）

### 讨论可读性与维护

- **表达**：`hard to follow`（不容易理解）；`a clearer name`（更清楚的名字）；`extract a helper`（提取辅助函数）
- **例句**：This condition is hard to follow. Could we give it a clearer name?（这个条件不容易理解。能给它起个更清楚的名字吗？）
- **例句**：We could extract a helper if this logic is used in more than one place.（如果这段逻辑在多处使用，可以提取辅助函数。）

### 解释自己的选择

- **表达**：`choose this approach`（选择这个方案）；`consider an alternative`（考虑其他方案）；`be open to changing it`（愿意调整）
- **例句**：I chose this approach because it's easier to test.（我选这个方案是因为它更容易测试。）
- **例句**：I considered a shared component, but there's only one use case so far. I'm open to changing it later.（我考虑过共享组件，但目前只有一个使用场景；以后可以调整。）

### 跟进评审

- **表达**：`review this today`（今天评审）；`block the release`（阻碍发布）；`no rush`（不着急）
- **例句**：Could you review this today? It's blocking the release.（今天能评审一下吗？它卡住发布了。）
- **例句**：Could you review the cleanup PR when you have time? No rush.（有空时能评审一下清理代码的 PR 吗？不着急。）

### 处理版本历史

- **表达**：`rebase onto main`（基于主分支变基）；`cherry-pick a commit`（挑选提交应用到另一分支）；`revert a commit`（用新提交撤销旧提交）
- **例句**：I'll rebase onto the latest main before merging.（合并前，我会基于最新主分支变基。）
- **例句**：We can cherry-pick the fix into the release branch without merging the other changes.（我们可以只把修复提交挑到发布分支，不合并其他改动。）
- **例句**：We reverted the commit after it caused a regression.（那次提交引起回归问题后，我们把它撤销了。）

### 合并后的确认

- **表达**：`merge the PR`（合并 PR）；`deploy the change`（部署改动）；`verify after deployment`（部署后验证）
- **例句**：The PR has been merged, but the change won't be live until the next deployment.（PR 已合并，但下次部署前改动不会上线。）
- **例句**：I'll verify the change after deployment.（部署后我会验证这项改动。）
